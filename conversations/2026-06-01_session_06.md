### 2d. Implement the Monte Carlo engine and calibration pipeline

9. `stablecoin_ms/montecarlo.py` — implemented `sample_theta` (informative-prior branch when τ > 0, fallback Gaussian dispersion otherwise), `run_scenario` (iterates over `n_draws`, calls `fixed_point.solve`, returns a list of `DrawResult`, optionally writes a manifest JSON to `out_dir`), `aggregate_moments` (mean / std / min / max / p95 of secondary price, large-depeg frequency under $\bar p = 0.975$, mean absolute depeg in bps, fraction converged, per-class mean and std of redemption rate). The placeholder p95 expression from the first draft was cleaned to `np.quantile`.
10. `stablecoin_ms/calibration.py` — implemented the ten-parameter calibration vector (four class sigmas, four secondary-block parameters ψ, ν, μ_q, ζ, and two θ-prior means for baseline and stress), `USDCMarch2023Targets.from_json` (loads the six moments from `data/processed/usdc_march2023_targets.json`), `template_scenario` (a baseline parameterised template), `apply_params` (returns a parameterised copy via `dataclasses.replace`), `model_moments_pair`, `usdc_loss` (weighted L2 with the prior weights tuned so that the small-magnitude baseline moments are not dominated by the basis-point-scale stress moments), and `calibrate_usdc` (Nelder-Mead minimiser with bound clipping; defaults set to keep the budget small).
11. Updated `tests/test_smoke.py::test_remaining_stubs_raise_not_implemented` to reflect that montecarlo and calibration are now implemented; remaining stubs are `cost_benefit.compute_cec_stablecoin` and `cost_benefit.breakeven_theta`.

### 2e. Smoke test the pipeline

12. Loaded the USDC targets from JSON, ran `run_scenario(N=20)` on the template scenario in 12.74 s (≈ 637 ms / draw — the Newton-Krylov solve dominates), and computed aggregate moments. Then evaluated `usdc_loss` at the template parameter vector (both scenarios, N=20 each) in 21.55 s. Loss = 18,152.85.
13. Diagnosed the gap. The template's baseline scenario is way off (mean p_sec 0.9824 vs target 1.0000, std 0.0136 vs target 0.0008, large_depeg_freq 0.30 vs target 0.00). Stress is closer but still mis-shaped (min 0.961 vs target 0.902 — model is too gentle on the tail; mean_abs_bps 375 vs target 240 — model is too punishing on average). The right calibration direction is to raise the convenience yield ω and lower ψ to keep baseline near par, while raising ν to extend the stress tail without inflating the mean.

### 2f. Performance note for session 07

14. The Newton-Krylov solve is the bottleneck at ~637 ms / draw. A full Nelder-Mead run (maxiter = 30, N = 200, two scenarios) would cost roughly 30 × 200 × 2 × 0.5 s ≈ 100 minutes. Session 07 should run the calibration in a background sub-agent and use the parent for analysis once the calibrated parameters land.
