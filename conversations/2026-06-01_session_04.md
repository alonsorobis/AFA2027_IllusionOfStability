## 2. AI actions in this session (chronological, summarised)

### 2a. Parent-session setup (before sub-agent delegation)

1. **DefiLlama encoding fix.** Patched `data/scripts/download_defillama.py` to pass `encoding="utf-8"` on every `Path.write_text` call. This kills the cp1252 crash on Tether's `₮` glyph that aborted the session-03 per-asset loop.
2. **Coinbase script pivot to Advanced Trade REST.** Rewrote `data/scripts/download_coinbase.py` to call `https://api.coinbase.com/api/v3/brokerage/market/products/{product_id}/candles` with Unix-second `start`/`end` and the enum `granularity=ONE_HOUR`. Chunked at 300 candles per request. Smoke-tested with a 1-day window and got HTTP 400 `"valid product_id is required"` for USDC-USD. Diagnosed via the products catalogue endpoint that Coinbase Advanced Trade no longer lists `USDC-USD` (USDC is treated as ~USD natively). `USDT-USD` and `DAI-USD` are still available. Updated the script's default `PRODUCTS` tuple to `("USDT-USD", "DAI-USD")` and added an in-file note pointing to the CryptoCompare fallback for USDC.
3. **CryptoCompare script.** Created `data/scripts/download_cryptocompare.py` for `https://min-api.cryptocompare.com/data/v2/histohour?fsym=<X>&tsym=USD`. Chunks at 2000 candles per request, going backwards from `end` until `start`. Defaults: `USDC USDT DAI`. Smoke-tested for USDC over 2023-03-10 to 2023-03-13 and got 73 hourly rows, with the depeg starting cleanly at 21:00 UTC on March 10 (open 1.0000, close 0.9973).
4. **Compared USDC alternatives.** Probed Kraken and Binance for backup. Kraken's `OHLC` endpoint caps the public response at ≈720 candles which would force scraping for historical data; Binance has `USDCUSDT` but the pair was added with thin liquidity in early 2022 and returned 0 hourly rows for March 2023 in a smoke test. CryptoCompare returned a clean depeg cross-section. The author then chose the **hybrid: Coinbase Advanced Trade for USDT/DAI + CryptoCompare for USDC**, which matches the data lineage of Ahmed-Aldasoro-Duley (2024) Figure 1.
5. **BCB script cleanup.** Edited `data/scripts/download_bcb_crossborder.py` to drop the placeholder series id `21619` (which returned HTTP 406 in session 03). Kept the confirmed working series `27688` (160 obs).
6. **RPW manual XLSX.** The author dropped the latest available RPW dataset (Q3 2025) at `C:/Users/alons/Documents/Stablecoins/data/rpw_dataset_2011_2025_q3.xlsx` (50.8 MB). The parent session copied it into `data/raw/wb_remittance_prices_2011_2025q3_20260601.xlsx`, computed its SHA256 (`02e7ec01e461d027…`), confirmed the six sheets (Terms of Use, Methodology, Legend, Countries, Dataset up to Q1 2016, Dataset from Q2 2016) and appended a manifest row to `data/download_log.md` under a new "Session 04 — fixes and additions" header. A quick corridor cross-check raised a `ValueError` because the actual column names in the dataset sheet differ from the guess (`country_code_source`, `country_code_destination`, `period`); not blocking — flagged for session 05.
7. **`requirements.txt` updates.** Relaxed the `pyarrow` pin so Python 3.14 wheels are available (the venv that session 03 created uses Python 3.14.3); added `openpyxl>=3.1,<4` for reading the RPW XLSX.
